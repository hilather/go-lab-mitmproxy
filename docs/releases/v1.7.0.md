## Highlights

1.7.0 is a **minor** release after [v1.6.3](https://github.com/hilather/go-lab-mitmproxy/blob/v1.6.3/docs/releases/v1.6.3.md). Everything since v1.6.2 is v1.6.3 (h2 unread buffered DATA credit, [PR #78](https://github.com/hilather/go-lab-mitmproxy/pull/78)) plus this release. Native catalog stays **31** `/v1` rows. `features.get` stays 11 rows. MCP stays **2026-07-28**. No new YAML fields, capability IDs, apply verbs, or metrics. No fuzzer or exploit UX; D79 includes one guarded replay of a captured flow. **D7 stands.**

What this tag changes:

- Proxy, Reset and control-plane correctness ([PR #81](https://github.com/hilather/go-lab-mitmproxy/pull/81)): configured management TLS is enforced; Reset stages listener changes before committing; HTTP/2 and h2c responses stream incrementally under the capture cap (ADR 0019, D78); REST request envelopes reject unknown fields.
- HTTP/2 origin stream IDs follow opening-HEADERS wire order, fixing intermittent origin `PROTOCOL_ERROR` and proxy 502s; CI fuzz smoke and harness fixes ([PR #84](https://github.com/hilather/go-lab-mitmproxy/pull/84)).
- Frontend parity with every operator-facing REST/MCP capability is a project requirement (ADR 0020, D79; [PR #82](https://github.com/hilather/go-lab-mitmproxy/pull/82)), implemented with the missing browser workflows and a mandatory parity gate ([PR #83](https://github.com/hilather/go-lab-mitmproxy/pull/83)).
- The operator UI is redesigned to the approved oct03 mocks (ADR 0021, D80; [PR #85](https://github.com/hilather/go-lab-mitmproxy/pull/85)). Chrome only: request bodies are byte-identical.

## Added

- Flows: resume with omitted, empty, header or body edits; drop; guarded single replay with results; cancellable wait; complete server filters and all cursor pages; optional store-generation preconditions; complete escaped flow detail; selected paused flows follow SSE updates (#83).
- Configuration: validation, canonical YAML/JSON export with revision/drift details, and all eight live verbs (including full TLS, targets and store caps) through current-state JSON templates with plan review, idempotency-aware retries and apply (#83).
- Diagnostics for version, capabilities, schema, health and metrics; audit limit queries and full event lookup (#83).
- Mandatory frontend parity gate (`make test-ui-parity`): registry entries, apply verbs, contract review, reachable routes and named passing behavioral evidence; missing, skipped or failed evidence fails closed (#83).
- ADRs 0019 (D78), 0020 (D79) and 0021 (D80); [docs/15-operator-ui.md](https://github.com/hilather/go-lab-mitmproxy/blob/v1.7.0/docs/15-operator-ui.md).

## Changed

- Operator UI (#85): one in-page confirm (alertdialog, background `inert`, Cancel focused, Escape cancels) and one plan-review panel replace `window.confirm`; the plan review is a panel on Configuration and a drawer on Status. Flows status chips (All / Paused / 2xx / 4xx / 5xx · error) and a paused-request breakpoint card with Resume as the primary action and a danger Drop; a filters popover with ruleId suggestions and active-filter chips; Raw JSON tab. Configuration tabs (Live changes / Validate candidate / Export / Current state), eight operation templates and an Edit → Validate → Review plan → Apply stepper. Diagnostics tiles (liveness, readiness, version, protocols, metrics) and a filterable capabilities table with **Refresh all**. Audit split list/inspector with capability and result chips. Reset danger-filled button with an impact line (flow count and store generation from `GET /v1/status`). Local times with the ISO value in the tooltip. The D77 `ui.enabled` off-confirm text is unchanged.
- REST request envelopes reject unknown fields, including nested apply operations; errors name the rejected field. Candidate-state byte-size values are coerced once by the strict decoder (#81).
- HTTP/2 and h2c responses forward incrementally with bounded capture (ADR 0019). An oversized response paused on a shared HTTP/1.1 origin connection holds that connection until its unread body is consumed or closed (#81).
- Policy: ADR 0020 (D79) makes frontend parity with operator-facing REST/MCP capabilities a project requirement (#82).

## Fixed

- Management listeners honor configured TLS, require TLS 1.2 or newer, and reject plaintext; certificate/key files are validated before listeners open (#81).
- Reset preflights proxy, original-destination, management and metrics listener changes and applies them with the new snapshot; an occupied address is non-retryable `validation_failed` on REST and MCP, and a failed Reset keeps the old listeners, state and flows (#81).
- Bearer rotation invalidates browser sessions atomically; failed credential reloads keep existing sessions. Expired cached interception leaves are renewed (#81).
- HTTP/2: receive windows enforced for connection and stream DATA; invalid stream headers no longer tear down unrelated streams; empty trailer HEADERS omitted; stream cancellation unblocks stalled origin responses (#81). Concurrent origin requests allocate stream IDs in opening-HEADERS wire order (#84).
- Resume of spilled bodies is transactional; explicit empty edits stay distinct from omitted edits; untouched truncated tails are preserved (#81).
- Status live-apply works without `crypto.randomUUID` on remote HTTP origins (#81). Browser API errors keep field violations, remediation, retryability and revision; `409` messages name the conflict (#83). Masthead fixed at 56px with Sign out outside the chip row; no mid-word breaks on Status; one danger text colour (#85).
- CI: failures propagate through `tee`; fuzz smoke uses 500,000 executions per target instead of a five-second deadline; container smoke origins run on an isolated Docker network (#81, #84).

## Removed or deprecated

- None. No YAML keys, REST paths, MCP tools, capability IDs, or apply verbs were removed. The browser `window.confirm` dialogs are replaced by in-page confirms (UI only).

## Security

- Management TLS, when configured, is now enforced: plaintext is rejected and TLS 1.2+ is required. Health probes must use HTTPS in that case.
- Lab static bearer unchanged; unauthenticated `GET /v1/flows` / `GET /v1/features` / `GET /v1/status` stay 401. Bearer rotation now revokes browser sessions atomically.
- Data-plane `spec.proxy.httpAuth` remains opt-in and **off by default**. Handshake failure on intercept-eligible CONNECT still does not fall back to a blind tunnel (D20).
- In-page confirms keep the D77 gated off-confirm text and semantics. Bearer session, CSRF, no token in web storage. Captured HTML stays escaped text.
- `make security-scan` runs govulncheck.

## Proxy behavior

- Standalone default remains `127.0.0.1:8888`. Empty `spec: {}` hop behavior and D22-carve gates are unchanged.
- HTTP/2 and h2c responses stream incrementally; the capture cap bounds memory (ADR 0019). Receive-window enforcement, stream isolation, empty-trailer omission and wire-ordered origin stream IDs are listed under Fixed.
- Cleartext HTTP/1.1 response bodies are still not flushed per write; small chunked or SSE events can wait for a buffer flush (known limitation).

## Flow-inspector UI

- Still embedded at `/` when `spec.ui.enabled` is true; `enabled: false` 404s the inspector routes and keeps REST/MCP.
- D79 parity: every operator-facing REST/MCP capability has a reachable browser workflow (flow resume/drop/replay/wait, all eight live verbs, export, diagnostics, audit lookup). Advanced configuration remains a JSON editor; rule editing is not a visual builder.
- D80 redesign as listed under Changed. New reads reuse existing GETs (Reset reads `/v1/status`; Diagnostics **Refresh all** re-runs the existing reads).
- No fuzzer, repeater, exploit, SSL-strip, Relay, or mitmweb clone.

## Compatibility and migration

- Existing v1.6.3 YAML keeps working without edits.
- REST clients must remove misspelled or extra request fields; they now fail instead of being ignored.
- Deployments with management TLS configured must use HTTPS, including management health probes.
- Reset reserves changed listener addresses before retiring old sockets. Overlapping same-port changes (for example `127.0.0.1:8888` to `0.0.0.0:8888`) fail with `validation_failed`; restart with the new bootstrap or Reset through a free intermediate port.
- Browser automation that answered `window.confirm` must use the in-page confirm dialogs.
- Rollback is a process restart onto v1.6.3. Captured flows are discarded on restart.

## Known limitations

See [docs/known-limitations.md](https://github.com/hilather/go-lab-mitmproxy/blob/v1.7.0/docs/known-limitations.md).

- Oversized response breakpoints on a shared HTTP/1.1 origin connection hold that connection until the body is consumed or closed (ADR 0019).
- Cleartext HTTP/1.1 response bodies are not flushed per write.
- Management adapter settings still need a restart after configuration changes.
- Request-phase Resume leaves the original breakpoint record `open` and inserts the final capture under a separate ID.
- HTTP/3 / QUIC out. No Python mitmproxy wrap, TPROXY, or reverse-proxy mode. Data plane stays unauthenticated unless `httpAuth` is enabled.
- No published image digest, SBOM, or provenance from this tag.
