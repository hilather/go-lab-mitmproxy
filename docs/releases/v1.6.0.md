## Highlights

1.6 is **operator SPA live-apply** plus an origin-h2 completeness fix. [PR #70](https://github.com/hilather/go-lab-mitmproxy/pull/70) exposes the live apply verbs the control plane already had, so Status is no longer chrome-only leftover from [v1.5.0](https://github.com/hilather/go-lab-mitmproxy/blob/v1.5.0/docs/releases/v1.5.0.md). [PR #69](https://github.com/hilather/go-lab-mitmproxy/pull/69) forwards origin-h2 request DATA and response trailers. Native catalog stays **31** `/v1` rows. `features.get` stays 11 rows. MCP stays **2026-07-28**. No new YAML fields, capability IDs, apply verbs, or metrics. No fuzzer, repeater, or exploit UX. **D7 stands.** D22-carve stays (websocket / connect / absoluteForm default **on**).

What this tag changes:

- Status live-apply panels: `replaceTLS`, `replaceHTTPAuth` (407 file-ref users), `replaceRules` (items JSON, not a visual builder), `replaceAdmission`, and nested `replaceCompat` `{ compat: { flowREST } }`.
- Compact `status.features` panel: `httpAuth` badge plus Reset-required 1.2 flags as muted text (one catalog `Reset required` link).
- ADR 0018 / **D77**: Status may apply `ui.enabled` after a gated off-confirm. Recovery is REST/MCP (or bootstrap YAML + Reset).
- Header intercept chip reads live `GET /v1/state` `canonical.spec.tls.ports` (never hardcoded `:443 intercept only`).
- Inspector Frames tab badges GET-by-id `frames[].action` `drop` / `block`.
- Origin-h2 (`protocols.http2.origin`) now forwards inner POST/PUT/PATCH/gRPC request DATA and gRPC `grpc-status` / other response trailers.

## Added

- ADR [0018](https://github.com/hilather/go-lab-mitmproxy/blob/main/docs/adr/0018-status-ui-enabled-apply.md): **D77** — Status may apply `ui.enabled` via the existing `setFeature` verb after a gated confirm. Confirm runs only when turning **off**. Off-confirm text says all inspector routes (`/`, `/status`, `/flows/…`) 404. REST/MCP stay up. Recovery is REST/MCP `setFeature ui.enabled: true` or bootstrap YAML + Reset. Apply mode stays live. Reset-only IDs stay Reset-only. HTTP 407 stays `replaceHTTPAuth`, not a Features-table switch.
- Operator Status live-apply panels for the existing verbs `replaceTLS`, `replaceHTTPAuth` (407 file-ref users), `replaceRules`, `replaceAdmission`, and nested `replaceCompat` `{ compat: { flowREST } }`. A flat `{enabled, pathPrefix}` under `compat` unmarshals to a zero `FlowREST` and disables `/compat`; the SPA posts the nest. No new capability ID. Catalog stays **31**.
- Status compact `status.features` panel: additive `httpAuth` badge (K10 reopen already on `status.get`) plus Reset-required 1.2 flags as muted text. One catalog `Reset required` link to `/reset`. `httpAuth` is **not** a `setFeature` ID.
- Header intercept-ports chip from live `GET /v1/state` `canonical.spec.tls.ports`. Signed-in text is `:{ports} intercept` when `spec.tls.intercept` is true (e.g. `:443 intercept` or `:443,:8443 intercept`), `intercept off` when intercept is false, and `intercept ports unknown` until state loads. Empty ports still normalize to `[443]`. The chip never falls back to hardcoded `:443 intercept only`. `GET /v1/status` still has no `tls.ports` field.
- Inspector Frames tab badges `drop` / `block` from GET-by-id `frames[].action` (omitted when forwarded). The field already existed on v1.4.0.

## Changed

- None. No YAML keys, REST paths, MCP tools, capability IDs, apply verbs, or metrics were renamed. Status leftover **behavior** from v1.5.0 (chrome only; no live-apply panels; `ui.enabled` read-only; hardcoded intercept chip; Frames without action badges) is superseded by the Added surfaces above.

## Fixed

- Origin h2 (`protocols.http2.origin`) now forwards inner POST/PUT/PATCH/gRPC request DATA. `http2x.OriginConn` treated `ContentLength == 0` as no body, so reconstructed inner streams (h2 often omits content-length) sent HEADERS with END_STREAM and dropped the payload.
- Origin-h2 `http2x.OriginConn` now surfaces trailing HEADERS on `Response.Trailer` (and skips 1xx informational HEADERS). Live intercept with `protocols.http2.origin` forwards gRPC `grpc-status` / other response trailers to the inner client and stores them on the flow instead of dropping the second HEADERS block.

## Removed or deprecated

- None. No 1.0, 1.1, 1.2, 1.3, 1.4, or 1.5 YAML keys were removed. The v1.5.0 hardcoded `:443 intercept only` chip copy is gone from the running SPA; CONNECT footer / `TUNNEL_REASON` stay overlay `tls.ports:[443]`.

## Security

- Unchanged from v1.5.0: lab static bearer; unauthenticated `GET /v1/flows` / `GET /v1/features` / `GET /v1/status` stay 401; no HTTP Basic on management (D6); resolve-then-guard Dial; reserved attack keys stay forbidden; image UID `65532`, scratch, no `CAP_NET_ADMIN`.
- Data-plane `spec.proxy.httpAuth` remains opt-in and **off by default**. Empty `spec: {}` stays an unauthenticated HTTP hop. Status now exposes `replaceHTTPAuth`; enabling 407 on a published bind is still operator risk and is **not** a network boundary.
- Handshake failure on intercept-eligible CONNECT still does not fall back to a blind tunnel (D20).
- D77 gated off-confirm: turning `ui.enabled` off 404s every inspector route on the next UI request. REST/MCP stay up so an administrator can recover without the SPA. Cancel posts nothing.
- Bearer session, CSRF, skip-link, no token in web storage. Captured HTML stays escaped text. No fuzzer, repeater, exploit, or SSL-strip UX.
- `make security-scan` runs govulncheck.

## Proxy behavior

- Standalone default remains `127.0.0.1:8888`. Empty `spec: {}` still 101-copies WebSocket, accepts HTTP CONNECT, accepts absolute-form `http://`, and does not 407. D22-carve hop gates stay default **on**.
- Origin-h2 multiplex (`protocols.http2.origin`, Reset-only) now sends request DATA when the inner stream has a body even if content-length is omitted, and forwards origin trailing HEADERS (including gRPC `grpc-status`) to the inner client and the flow store. Flag-off still transcodes h2→h1 (D44). h2→h1 request trailers toward origin stay dropped (`labmitm_h2_trailer_dropped_total`).
- Data plane is still unauthenticated unless the operator enables `httpAuth`. Do not publish without a network boundary.

## Flow-inspector UI

- Still embedded at `/` when `spec.ui.enabled` is true. `enabled: false` 404s `/` (and `/status`, `/flows/…`) and keeps REST/MCP.
- Split-pane inspector from v1.5.0 is unchanged: the live list stays mounted; selection on `/` and `/flows/:id` drives Request / Response / TLS (Trailers / Frames / gRPC when present). Completed raw CONNECT is still a tunnel-not-decrypt summary.
- Header intercept chip is live `GET /v1/state` `canonical.spec.tls.ports`. CONNECT footer / `TUNNEL_REASON` stay overlay/default copy (`tls.ports:[443]`). HTTP CONNECT captures still store hostname only.
- Status lists the 11-row `features.get` catalog. Administrators toggle live `setFeature` hop/accept rows **including** gated `ui.enabled` off-confirm (D77). Viewers stay badge-only.
- Status live-apply panels: `replaceTLS` (intercept + ports; generate-mode CA rotates when the TLS spec changes), `replaceHTTPAuth` (enabled / realm / file-ref users), `replaceRules` (enabled + items JSON), `replaceAdmission`, nested `replaceCompat`. Apply uses existing `POST /v1/changes:apply` (OCC `expectedRevision`, new UUID idempotency key, optional reason, CSRF).
- Compact `status.features`: `httpAuth` badge plus Reset-required 1.2 flags as muted text. Reset-only catalog rows still link to `/reset`.
- Frames tab badges `drop` / `block` from GET-by-id `frames[].action`.
- No Status editors for `replaceTargets` / `replaceStoreCaps`. Rules items are a JSON textarea, not a visual rule builder. Reset-only knobs stay Reset-only.
- No fuzzer, repeater, exploit, SSL-strip, Relay, or mitmweb clone.

## Known limitations

See [docs/known-limitations.md](https://github.com/hilather/go-lab-mitmproxy/blob/v1.6.0/docs/known-limitations.md).

- HTTP/3 / QUIC out. GSSAPI never selected. grpc-web envelope stays opaque. No `.proto` registry.
- Nested inner CONNECT without `:protocol` still RST, **no flow**. Unspecified BIND DST is rejected.
- 1.2 h2c RFC 9113 CONNECT is not `protocols.connect`. 1.2 `extendedConnect` websocket is not `protocols.websocket`.
- No Python mitmproxy / mitmdump / mitmweb wrap. No addon VM.
- No TPROXY in the appliance. No reverse-proxy / ingress. Orig-dest is Linux-only.
- Compat is a bounded subset. No HAR export in this program.
- Data plane stays unauthenticated unless `httpAuth` is enabled. HTTP 407 and SOCKS user-pass are not network boundaries.
- Orig-dest bind, listener addresses, management TLS, `metrics.listen`, and 1.2 nested flags (including `inspectFrames`) are Reset-only. Store is still ephemeral, single replica.
- No Status editors for `replaceTargets` / `replaceStoreCaps`. Rules items are a JSON textarea, not a visual rule builder. Reset-only knobs stay Reset-only.
- CONNECT footer / `TUNNEL_REASON` stay overlay/default copy (`tls.ports:[443]`). They do not read live `tls.ports`. `GET /v1/status` has no `tls.ports` field.
- `throttle` is not a connection shaper. Hang holds admission. `payloadContains` cannot see frames larger than the pinned visibility cap.
- No fuzzer, repeater, exploit, SSL-strip, or payload-generator UX.
- No published image digest, SBOM, or provenance from this tag.
- Overlay intercept is HTTPS `:443` only. LabLDAP/TacLab TLS is tunnel-not-decrypt.
