## Highlights

1.3 lets QA **toggle hop/protocol support live** through the same REST `/v1` and MCP `POST /mcp` control plane that already mutates rules, TLS, targets, and admission. Empty `spec: {}` hop behavior stays 1.0 (HTTP/1.1, SOCKS-close, 101-copy). **D7 stands.**

What this tag adds:

- **D51'** (ADR 0013): hop/accept flags the running process already consults from the session snapshot or `liveSpec()` are live-applyable via `setFeature` (and `replaceCompat` for the compat subtree) **without Reset and without wiping the flow inbox**. Orig-dest **bind**, listener addresses, management TLS files, `metrics.listen`, and 1.2 nested flags stay Reset-only.
- **D22 carve**: `protocols.websocket` / `connect` / `absoluteForm` default **on** at decode so omitting them does not change 1.0 hops. 1.1 opt-in and 1.2 flags stay default-off.
- Fail-closed disable: 403 `forbidden` before rules and origin Dial. Inner HTTP/1.1 websocket 403 keeps the CONNECT.
- Listing: `GET /v1/features`, MCP `mitm_features_list` / `labmitm://features`, and the Status page. Native catalog is **31** `/v1` rows.
- Replay fixes that landed after v1.2.0 (hostname-only `Host` uses the captured URL port; HTTPS replay closes the one-shot origin TLS conn).

## Added

- ADR [0013](https://github.com/hilather/go-lab-mitmproxy/blob/v1.3.0/docs/adr/0013-live-protocol-feature-gates.md): D51' live hop/accept vs Reset bind; D22 carve for 1.0-preserving gates.
- Nested hop gates `spec.protocols.websocket.enabled`, `spec.protocols.connect.enabled`, `spec.protocols.absoluteForm.enabled` (`ProtocolGateSpec` objects, not bare bools). `WebSocketSpec.Enabled` is additive beside `inspectFrames`. Canonicalize of empty `spec: {}` grows those three `enabled: true` objects.
- Plan/apply verbs `setFeature` and `replaceCompat`. Applyable IDs: `protocols.http2`, `protocols.websocket`, `protocols.connect`, `protocols.absoluteForm`, `listeners.proxy.acceptSOCKS5` / `acceptSOCKS4`, `compat.flowREST` (enabled via `setFeature`; enabled **and** `pathPrefix` via `replaceCompat`), `rules.enabled` (items unchanged), `ui.enabled`. Rejected: `listeners.originalDestination` (Reset), `tls.intercept` (use `replaceTLS`; generate-mode CA still rotates when the TLS spec changes). Plan warns `live_next_connection`.
- Capability `features.get` (`GET /v1/features`, `mitm_features_list`, `labmitm://features`, `mitm.read`). Inserted after `status.get`. 11-row derived catalog. Compact `status.features` five 1.1 booleans stay on `status.get`. Mutation stays `changes.plan` / `changes.apply`.
- Status Features table. Administrators toggle live `setFeature` hop/accept rows via `POST /v1/changes:apply` (`apiFetch`, CSRF). **No Status toggle for `ui.enabled`.** Reset-only rows link to `/reset`. Viewers are badge-only.
- QA bootstrap [examples/qa-websocket-off.yaml](https://github.com/hilather/go-lab-mitmproxy/blob/v1.3.0/examples/qa-websocket-off.yaml) (`protocols.websocket.enabled: false`).
- Proxy reject metric reasons `websocket`, `connect`, `absolute_form`. Captured `Flow.Error=forbidden`.

The 1.2 appliance (BIND/UDP/user-pass, WS frames, h2c, Ext CONNECT, origin `h2`, gRPC decode, PUSH capture) is included in this tag. See [docs/releases/v1.2.0.md](https://github.com/hilather/go-lab-mitmproxy/blob/v1.3.0/docs/releases/v1.2.0.md).

## Changed

- D51 is replaced by D51' for hop/accept booleans. 1.2 nested flags (`inspectFrames`, `http2.clientCleartext` / `origin` / `extendedConnect` / `capturePush` / `grpcDecode`, `acceptBind` / `acceptUDPAssociate` / `acceptUserPass`) remain Reset-only.
- Operator residual ([docs/known-limitations.md](https://github.com/hilather/go-lab-mitmproxy/blob/v1.3.0/docs/known-limitations.md)) documents the live vs Reset split. Overlay comments no longer claim catalog 30 or that 1.1 hop/accept flags are Reset-only.
- Compat flow REST enable is live `setFeature` / `replaceCompat` (prefix collision still `validation_failed`). `/compat` stays a side table (ADR 0011).

## Fixed

- Replay of a captured flow Dials the origin port from the stored URL when `Host` is hostname-only (intercept stores `host=127.0.0.1` and `url=https://127.0.0.1:18443/ok`). Non-default-port HTTP and HTTPS lab origins no longer fail with `upstream request failed` after defaulting to `:80` / `:443`.
- HTTPS `proxy.Replay` closes the one-shot origin TLS connection after the response body is drained (HTTP/1.1 Transport and 1.2 `NewOriginTransport` h2). Repeated inspector/REST/MCP HTTPS replays no longer leak idle FDs or persistConns per call.
- AGENTS.md and the numbered pack no longer concatenate 1.1/1.2 keep-both leftovers. `make test-docs` rejects stale “later PR” / duplicate table-row invariants.

## Removed or deprecated

- None. No 1.0, 1.1, or 1.2 YAML keys were removed. There is no `replaceProtocols` / `replaceProxyAccept`. `setFeature` of `tls.intercept` is rejected (keep `replaceTLS`).

## Security

- Default management auth is still lab static bearer. Unauthenticated `GET /v1/features` is 401. `features.get` is `mitm.read`. `setFeature` rides `changes.apply` (`mitm.admin` only).
- Enabling SOCKS5 on a published `:8888` still makes an unauthenticated SOCKS CONNECT proxy. Default remains false. Target guards (D16) still run after SOCKS parse. Bind stays loopback unless the operator already published it.
- Handshake failure on intercept-eligible CONNECT still does not fall back to a blind tunnel (D20). Disabled websocket does not strip `Upgrade` and forward as ordinary HTTP.
- Status cannot toggle `ui.enabled` (that 404s the SPA with no in-browser recovery). REST/MCP `setFeature` of `ui.enabled` remains allowed.
- Attack-tool reserved keys stay forbidden. Image UID `65532`, scratch, no `CAP_NET_ADMIN`.
- `make security-scan` runs govulncheck.

## Proxy behavior

- Standalone default remains `127.0.0.1:8888`. Empty `spec: {}` still 101-copies WebSocket, accepts HTTP CONNECT, and accepts absolute-form `http://`.
- `protocols.websocket.enabled: false`: 403 before rules/DNS/Dial on both `:8888` absolute-form and orig-dest origin-form HTTP. Inner HTTP/1.1 403 omits `Connection: close` and keeps the CONNECT (`roundTripInner` `stop=false`). Inner h2 Upgrade remains D48 RST. 1.2 `extendedConnect` / h2c `:protocol=websocket` are **not** this gate.
- `protocols.connect.enabled: false`: forward-proxy HTTP CONNECT 403 after orig-dest (D57 CONNECT stays 400), before Hijack/`metrics.accept()`. SOCKS CONNECT is a different ID.
- `protocols.absoluteForm.enabled: false`: legal `http://` absolute-form 403. Absolute `https://` stays 400 `absolute_https`. Orig-dest origin-form is not this flag (D31).
- `protocols.http2.enabled` and SOCKS accept flags were already read from the session snapshot / `liveSpec()`; `setFeature` now writes them without Restart.
- Data plane is still unauthenticated. Do not publish without a network boundary.

## Flow-inspector UI

- Still embedded at `/` when `spec.ui.enabled` is true. `enabled: false` 404s `/` and keeps REST/MCP.
- Status lists the 11-row catalog (on/off, live/reset). Admin live `setFeature` toggles except `ui.enabled`. No new `/features` route. No fuzzer, repeater, exploit, SSL-strip, Relay, or mitmweb clone.

## Compatibility and migration

- Operators on v1.2.0 keep existing YAML working without edits. Empty `spec: {}` is still a 1.0 hop process (101-copy, CONNECT on, absolute-form on).
- Canonicalize of empty spec **grows** `spec.protocols.websocket|connect|absoluteForm.enabled: true` (plus existing `inspectFrames: false`). GitOps diffs of canonicalize output will show those three objects.
- MCP/REST clients that assumed a frozen 30-row catalog must accept `features.get` / `mitm_features_list` (31 rows). Existing IDs are not renamed.
- Hop/accept flags that were Reset-only in 1.1/1.2 (`protocols.http2.enabled`, SOCKS accept, `compat.flowREST.enabled`) can now `setFeature` without wiping flows. Orig-dest bind and 1.2 nested flags still need Reset.
- MCP clients still speak `2026-07-28` unless `allowLegacyClients: true`.
- Compat is **not** mitmproxy 11. IDs are ULIDs.
- Rollback is process restart onto v1.2.0. Captured flows are discarded on restart.
- Overlay intercept is still HTTPS `:443` only. LabLDAP/TacLab TLS is tunnel-not-decrypt.

## Known limitations

See [docs/known-limitations.md](https://github.com/hilather/go-lab-mitmproxy/blob/v1.3.0/docs/known-limitations.md).

- HTTP/3 / QUIC out. GSSAPI never selected. grpc-web envelope stays opaque. No `.proto` registry.
- Nested inner CONNECT without `:protocol` still RST, **no flow**. Unspecified BIND DST is rejected.
- 1.2 h2c RFC 9113 CONNECT is not `protocols.connect`. 1.2 `extendedConnect` websocket is not `protocols.websocket`.
- No Python mitmproxy / mitmdump / mitmweb wrap. No addon VM.
- No TPROXY in the appliance. No reverse-proxy / ingress. Orig-dest is Linux-only.
- Compat is a bounded subset. No HAR export in this program.
- Data plane stays unauthenticated. SOCKS user-pass is not a network boundary.
- Orig-dest bind, listener addresses, management TLS, `metrics.listen`, and 1.2 nested flags are Reset-only. Store is still ephemeral, single replica.
- No Status toggle for `ui.enabled`.
- No published image digest, SBOM, or provenance from this tag.
- Overlay intercept is HTTPS `:443` only. LabLDAP/TacLab TLS is tunnel-not-decrypt.
