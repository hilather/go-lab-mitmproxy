## Highlights

1.7.3 is a **patch** after [v1.7.2](https://github.com/hilather/go-lab-mitmproxy/blob/v1.7.2/docs/releases/v1.7.2.md): the Go toolchain moves to go1.26.9 and `golang.org/x/net` to v0.60.0 ([PR #97](https://github.com/hilather/go-lab-mitmproxy/pull/97)), opt-in HTTP proxy auth closes the TCP connection after a 407 to CONNECT, web development dependencies move in the lockfile only ([PR #95](https://github.com/hilather/go-lab-mitmproxy/pull/95), [#96](https://github.com/hilather/go-lab-mitmproxy/pull/96)), and the image build context gains a `.dockerignore` ([PR #100](https://github.com/hilather/go-lab-mitmproxy/pull/100), [#101](https://github.com/hilather/go-lab-mitmproxy/pull/101), [#102](https://github.com/hilather/go-lab-mitmproxy/pull/102)). The embedded SPA (`internal/web/dist`) is byte-identical. Native catalog stays **31** `/v1` rows. `features.get` stays 11 rows. MCP stays **2026-07-28**. There are no new YAML fields, REST fields, MCP tools, capability IDs, apply verbs or metrics. **D7 stands.**

What this tag changes:

- Build and CI use Go **1.26.9** (`toolchain go1.26.9`, CI `GO_VERSION`, image build stage `golang:1.26.9-alpine`). `golang.org/x/net` is v0.60.0. An intermediate pin to go1.26.8 ([PR #94](https://github.com/hilather/go-lab-mitmproxy/pull/94)) is superseded by #97.
- With opt-in HTTP proxy auth (D76, default off), a 407 to CONNECT carries `Connection: close` and the proxy closes that TCP connection. Clients retry CONNECT with credentials on a **new** connection. Absolute-form 407 still retries on the same connection. **Helm:** a chart or client that enables `spec.proxy.httpAuth` and retries a rejected CONNECT on the same TCP connection must open a new connection. A chart that leaves `httpAuth` omitted or false is unchanged.
- `web/package-lock.json` only: `source-map-js` 1.2.2, `undici` 8.10.2, `vitest` / `@vitest/*` 4.1.11. Built web assets are byte-identical.
- The production image build context excludes `.git`, `.github`, `docs`, and every `testdata` directory. `make test-container` still bind-mounts its fixtures from the host checkout.

## Proxy behavior

- With opt-in HTTP proxy auth (`spec.proxy.httpAuth.enabled`, D76), a 407 to CONNECT now carries `Connection: close` and the proxy closes that TCP connection. `writeProxyAuthChallenge` still omits `Connection: close`; Go 1.26.9+ `net/http` adds it and closes the connection because it no longer reuses a connection after a CONNECT it did not hijack. Clients retry CONNECT with credentials on a new TCP connection. The transcript `http-auth-connect-retry.txt` is that second connection, and a live check asserts EOF after the 407 ([PR #98](https://github.com/hilather/go-lab-mitmproxy/pull/98)). Absolute-form 407 is unchanged (keep-alive retry on the same connection). A 407 CONNECT is still not hijacked (D19).
- **Helm:** charts and clients that enable `spec.proxy.httpAuth` and retry a rejected CONNECT on the same TCP connection (the v1.7.2 behaviour) must open a new connection after this tag. Charts that leave `httpAuth` omitted or false are unchanged. This is not a YAML migration.
- Otherwise unchanged from v1.7.2. Standalone default remains `127.0.0.1:8888`. Empty `spec: {}` hop behavior, D22-carve gates and bounded HTTP/2 streaming (ADR 0019) are unchanged. `httpAuth` omitted still means off.

## Compatibility and migration

- Existing v1.7.2 YAML keeps working without edits. REST/MCP clients need no changes. `httpAuth` omitted still means off.
- **Helm / httpAuth clients:** a 407 to CONNECT closes the TCP connection. Retry CONNECT with credentials on a new connection. Absolute-form 407 still retries on the same connection. This is client behaviour, not a config edit.
- Contributors and CI build with Go 1.26.9. The image build stage is `golang:1.26.9-alpine`.
- Contributors who rebuild `web/` stay on Node 22.22.2+ (CI 22.23.3). The lockfile bumps do not change `web/package.json` engines or the embedded assets.
- Rollback is a process restart onto v1.7.2. Captured flows are discarded on restart. A rolled-back process again accepts a CONNECT retry on the same TCP connection after a 407.

## Known limitations

See [docs/known-limitations.md](https://github.com/hilather/go-lab-mitmproxy/blob/v1.7.3/docs/known-limitations.md). Unchanged from v1.7.2.

- Oversized response breakpoints on a shared HTTP/1.1 origin connection hold that connection until the body is consumed or closed (ADR 0019).
- Cleartext HTTP/1.1 response bodies are not flushed per write.
- Management adapter settings still need a restart after configuration changes.
- Request-phase Resume leaves the original breakpoint record `open` and inserts the final capture under a separate ID.
- HTTP/3 / QUIC are out. There is no Python mitmproxy wrap, TPROXY, or reverse-proxy mode. The data plane stays unauthenticated unless `httpAuth` is enabled.
- No published image digest, SBOM, or provenance from this tag.
- Focus follow-ups not in this tag:
  - If the Status `GET /v1/state` or plan request fails, no drawer opens, so focus stays on the page body in Chrome after the busy control is disabled.
  - Configuration page confirms still capture the opener when the confirm opens, not at click time; they reach `#app-main` through the fallback.
  - An optional cleanup of the disabled-opener check (`nativelyDisabled` versus a `:disabled` match) is deferred.
