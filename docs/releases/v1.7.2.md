## Highlights

1.7.2 is a **patch** of one Unreleased operator-UI fix and one toolchain change after [v1.7.1](https://github.com/hilather/go-lab-mitmproxy/blob/v1.7.1/docs/releases/v1.7.1.md): Status plan review and confirm focus restore ([PR #91](https://github.com/hilather/go-lab-mitmproxy/pull/91)), and the operator-console Node floor 22.22.2+ with CI on Node 22.23.3 ([PR #92](https://github.com/hilather/go-lab-mitmproxy/pull/92)). The focus bug was reproduced on v1.7.1 (`dd2b0e49`) and in QA, and post-merge QA passed on `369c5d3c`. The UI change is focus behaviour only, and request bodies are byte-identical. The Node change affects building `web/` and CI only; the binary, embedded SPA (`internal/web/dist`) and image are unchanged by it. Native catalog stays **31** `/v1` rows. `features.get` stays 11 rows. MCP stays **2026-07-28**. There are no new YAML fields, REST fields, MCP tools, capability IDs, apply verbs or metrics. **D7 stands.**

What this tag changes:

- On **Status**, closing **Review planned change** (Escape, **Discard plan**, **Apply reviewed changes** or a backdrop click) now returns focus to the main content (`#app-main`) instead of the page body. A backdrop click on a confirm no longer drops focus to the page body: it returns to the opener while that control is still usable (for example the Status `ui.enabled` switch), otherwise to `#app-main` (Configuration confirms, whose Apply button is busy-disabled while the confirm is open).
- Confirms and the plan drawer share one focus fallback: the opener when it is still usable, otherwise `#app-main`.
- Building the operator console from source needs Node **22.22.2+**; CI's `web` job now runs Node 22.23.3 ([PR #92](https://github.com/hilather/go-lab-mitmproxy/pull/92)).

## Fixed

- Status plan review captures the opener when you click. Every Status apply form (feature switches, TLS, HTTP auth, rules, admission, compat) records the control at call entry, before the change is planned; a feature switch passes the clicked switch itself. Previously the opener was read after the state and plan requests, when the busy control was already disabled and Chrome had moved focus to `<body>`, so closing the drawer "restored" focus to `<body>`. Now Escape, **Discard plan** and **Apply reviewed changes** land on `#app-main` while the control is still busy. The drawer decides where focus goes when it closes, so the later end of the busy state cannot change it ([PR #91](https://github.com/hilather/go-lab-mitmproxy/pull/91)).
- One focus fallback for confirms and the plan drawer. Focus returns to the opener only if it is still in the page, is not `<body>` or `<html>`, and is not disabled or `aria-disabled`; otherwise it goes to `#app-main`. Disabled and `aria-disabled` openers already fell back in v1.7.1; detached, missing, `<body>` and `<html>` openers now also land on `#app-main` instead of the page body (or the root element) ([PR #91](https://github.com/hilather/go-lab-mitmproxy/pull/91)).
- Backdrop clicks keep focus off `<body>`. The plan-drawer and confirm backdrops now cancel the browser's default `mousedown` action before closing, so Chrome no longer moves focus to the page body after it was restored. A drawer backdrop click lands on `#app-main`, because the Status control is still busy; a confirm backdrop click returns to the opener if it is still usable and otherwise to `#app-main` ([PR #91](https://github.com/hilather/go-lab-mitmproxy/pull/91)).

## Known limitations

See [docs/known-limitations.md](https://github.com/hilather/go-lab-mitmproxy/blob/v1.7.2/docs/known-limitations.md).

- Oversized response breakpoints on a shared HTTP/1.1 origin connection hold that connection until the body is consumed or closed (ADR 0019).
- Cleartext HTTP/1.1 response bodies are not flushed per write.
- Management adapter settings still need a restart after configuration changes.
- Request-phase Resume leaves the original breakpoint record `open` and inserts the final capture under a separate ID.
- HTTP/3 / QUIC are out. There is no Python mitmproxy wrap, TPROXY, or reverse-proxy mode. The data plane stays unauthenticated unless `httpAuth` is enabled.
- No published image digest, SBOM, or provenance from this tag.
- Focus follow-ups not in this tag:
  - If the Status `GET /v1/state` or plan request fails, no drawer opens, so focus stays on the page body in Chrome after the busy control is disabled.
  - Configuration page confirms still capture the opener when the confirm opens, not at click time; they reach `#app-main` through the fallback.
  - An optional cleanup of the disabled-opener check (`nativelyDisabled` versus a `:disabled` match) is deferred.
